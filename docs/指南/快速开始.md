# 快速开始

## 目录布局

```text
仓库/
  index.html          入口：零配置外壳（DOM 容器 + 三个标签，不含项目信息）
  app/                外壳代码：markdown.js / main.js / style.css
  docs/               内容根：所有会被渲染成网页的东西，配置也在里面
    _config.json      站点配置：顶栏名、首页、清单文件名、大纲级别……
    README.md         首页（配置里的 home 指向它，所以 #/ 打开的就是它）
    _sidebar.md       左栏清单
    指南/ 参考/        正文与图片，路径一律相对 docs/
```

- 仓库根目录只放**外壳与项目自身**的东西；凡是会被渲染的内容都在 `docs/` 里；
- 内容目录不一定要叫 `docs`：默认就是它，外壳里的 `window.MD_SITE = { root: … }` 指哪就以哪为内容根；
- 如果 Markdown 就放在 `index.html` 旁边，在 `index.html` 里加一行 `window.MD_SITE = { root: '' }`
  即可（见 [站点配置](站点配置.md)）。

## 起服务

任意静态服务器都行，在仓库根目录下执行：

```bash
python3 -m http.server 8080          # 开发时够用，打开 http://localhost:8080/
```

```nginx
# 生产上就是一句话：静态目录 + index.html
location / {
    root /srv/md-site;
    index index.html;
}
```

> **必须走 HTTP**：正文是 `fetch()` 拿的，`file://` 协议下浏览器会直接拦掉。
> 所以「双击 `index.html` 就能看」这个用法不成立——这是设计边界，不是 bug。

## 内容根

- 正文、图片、`_sidebar.md` 里的条目，路径**一律相对内容根**（本仓库是 `docs/`），与 `index.html` 放在哪无关；
- 内容根是**真实边界**：`#/../README.md` 这类越界的路由得到 404 页，不会把内容根之外的文件渲染进来；
- 所以 `docs/` 可以整体换成别的项目：搬 Markdown、写清单，站点立刻变成那个项目的。
