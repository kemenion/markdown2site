# 站点配置

站点的配置住在**内容根里的 `_config.json`**（本站是 `docs/_config.json`）：外壳 `index.html` 与 `app/`
对具体项目一无所知，换项目 = 换内容根那个目录，配置跟着一起走。

```json
{
  "name": "阅读收集",
  "home": "README.md",
  "nav": "_sidebar.md",
  "toc": [2, 3],
  "sidebarExpanded": "all",
  "cacheVersion": "v1",
  "theme": "auto"
}
```

## 配置项

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `name` | `''` | 顶栏标题；留空则回落到清单里第一个文档的标题 |
| `home` | `README.md` | `#/` 指向的文件，相对内容根 |
| `nav` | `_sidebar.md` | 左栏清单文件，相对内容根；旧名 `sidebar` 仍然接受，见 [侧栏清单](侧栏清单.md) |
| `toc` | `[2, 3]` | 右栏大纲收录哪些级别，`[]` 关闭；左栏不挂大纲 |
| `sidebarExpanded` | `'all'` | 左栏分类的初始展开策略，见 [侧栏清单](侧栏清单.md) |
| `cacheVersion` | `''` | 破缓存版本号，内容更新后加一即可 |
| `theme` | `auto` | `auto` 跟随系统 / `light` / `dark` |

- 是 JSON，所以**不能写注释**：`_` 开头的键（例如 `"_comment"`）会被静默忽略，可以当注释位用；
- 拼错的键不会静默失效——控制台会 `console.warn` 提示不认识的键名。

## 配置从哪来：三层，后面的盖前面的

1. `app/main.js` 里的内置默认值（就是上表的「默认」列）；
2. 内容根里的 `_config.json`；
3. `index.html` 里可选的 `window.MD_SITE`——**优先级最高**，只用来覆盖，例如把内容根换到别处：

```html
<script>window.MD_SITE = { root: 'fixtures' };</script>
```

`root` 是唯一的例外：它必须在读 `_config.json` **之前**就定下来，所以只能写在 `window.MD_SITE` 里
（写进配置文件会被忽略，并给一条提示）。默认值是 `docs`，也就是入口旁边的 `docs/` 目录。

## 读不到配置怎么办

配置是「锦上添花」，不是「没它不行」：

- 没有 `_config.json`（404）→ 静默改用默认值，站点照常渲染；
- 文件不是合法 JSON → 一条 `console.warn` + 默认值，站点照常渲染；
- 所以删掉 `docs/_config.json` 也不会白屏，只是顶栏名回落成清单里的第一个文档。

## 改完怎么生效

1. 只改 `docs/_config.json`，`index.html` 与 `app/` 一概不用动；
2. 内容更新后把 `cacheVersion` 加一（例如 `v1` → `v2`）：它会拼到每个内容请求上，绕开浏览器缓存；
   配置文件自己是用 `no-store` 取的（也不带版本号），所以改完配置刷新就生效；
3. 刷新页面。站点是纯静态的，「部署」就等于把文件覆盖到服务器上。

## 部署注意：GitHub Pages 要加 `.nojekyll`

GitHub Pages 默认会跑一遍 Jekyll，而 Jekyll **不发布 `_` 开头的文件与目录**——`_config.json` 与
`_sidebar.md` 都在其中。在仓库根放一个空的 `.nojekyll` 文件即可让它们按普通静态文件发布；
不加的话，配置与清单都会 404（站点不会白屏，但会退回默认值 / 空左栏）。

## 主题与大纲

- `theme: 'auto'` 时跟随系统的 `prefers-color-scheme`；顶栏的 🌙 / ☀️ 按钮可以强制浅色或深色，
  选择记在 `localStorage` 的 `md-site-theme` 里，刷新后仍然生效；
- `toc` 决定右栏收哪些级别（本站是 h2 + h3），而**左栏永远只有文档条目**；
- 窄屏下左栏与大纲怎么变（抽屉 / 浮层）见 [界面与移动端](../参考/界面与移动端.md)。
