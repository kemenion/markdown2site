# 项目结构

## 仓库里的文件

```text
index.html              入口：零配置外壳（DOM 容器 + 三个标签），项目信息一概不在这里
app/markdown.js         解析器：parse(md) → AST（纯函数，不碰 DOM）
app/main.js             应用：读配置 / 路由 / 侧栏树 / 大纲 / 主题 / 渲染 / 交互
app/style.css           样式：三栏布局 + 浅深两套变量 + 响应式
docs/                   内容根（默认 root: 'docs'），可以整包搬去别的项目
  _config.json          站点配置：顶栏名、首页、清单文件名、大纲级别、缓存版本号、主题
  README.md             真实首页：home 指向它，所以 #/ 打开的就是它
  _sidebar.md           左栏清单（docsify 语法，可直接复用现有文件）
  指南/ 参考/            正文与图片，路径一律相对 docs/
```

- 根目录只放**外壳与项目自身的文件**；凡是会被渲染成网页的东西都在 `docs/` 里；
- 配置也算内容：`docs/_config.json` 跟着内容包走，换项目时外壳 `index.html` 一个字都不用改；
- 仓库里**没有**测试目录（`test/` 被 `.gitignore` 忽略、历史上从未入库），见下；
- 内容与外壳分离的好处：换项目 = 换 `docs/`，见 [指南总览](../指南/README.md)。

## 测试在哪

- 本站**不含**测试套件：`git clone` 下来的目录树就是上面列出的这些，没有 `test/`；
- 开发期的验证是「临时脚本 + 真实页面」：用 Node 直接调 `parse()` 断言 AST
  （解析器是纯函数、不碰 DOM，可以在 Node 里直接跑），再用 Playwright 打开 `index.html` 看渲染结果；
- 真实页面**读不到**站外文件（内容根边界只放行 `docs/`），所以内容根里没有任何测试残留。

```js
// 解析器可以直接在 Node 里跑（app/markdown.js 是唯一的依赖入口）
import { parse } from './app/markdown.js';
console.log(parse('# 标题').children[0].id);      // 标题
console.log(parse('```js\nlet a = 1;').warnings); // 代码块缺少收尾的 ```，已按到文末处理
```

## 已知限制（有意为之）

- **不**支持 setext 标题、引用式链接 `[a][b]`、Obsidian 双链 `[[a]]`、HTML 块内部的 Markdown；
- 提示区块（`::: tip` 等）与代码行高亮、标题自定义锚点是内置的三处少量拓展，类型名只认 `tip / info / warning / danger / details`；
- 文件开头的 YAML front matter 会被整块忽略（站点配置在 `_config.json` 里），见 [站点配置](../指南/站点配置.md)；
- 不做全文搜索 / mermaid / KaTeX / 插件系统 / i18n / 构建步骤（要这些就上 docsify）；
- Markdown 边缘写法的取舍（行尾 `\` 不换行、表格 `\|` 的转义规则、实体只认常用集合、嵌套强调不完美）见 [支持的语法](../指南/写内容/支持的语法.md)；
- 代码高亮是内置的简易分词器，不是 Prism；
- 左栏不会自动跟随文件系统：新文档要手写进 `_sidebar.md`；
- 左栏只列文档，不显示页面大纲；
- 左栏长标题的悬停展开是把条目原位复刻成一条 `fixed` 横条（`#sidebar-expand`）：左栏是纵向滚动区，横向溢出会被裁掉，纯 CSS 伸不出去；
- 需要现代浏览器（ES modules）。
